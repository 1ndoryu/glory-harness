## 089A-10 — Files y Git en el modo web

- Qué: el servidor `glory-harness web` no exponía endpoints de filesystem/Git
  (solo Tauri IPC), así que en el navegador Files/Git mostraban "no está
  disponible en el modo web". Port de la lógica pura de
  `desktop/src-tauri/src/filesystem.rs` + `git.rs` a endpoints HTTP de `cli`,
  raíz del workspace activo resuelta desde `comun.workspace` (via
  `area_activa`, con autorregistro). Sin watcher (ponytail, igual que 089A-9).

### Archivos nuevos
- `cli/src/comandos/web_datos/files.rs` — listado/lectura/búsqueda del workspace
  (límites `MAX_FILE_BYTES` 256 KiB, `MAX_ENTRIES` 500, `MAX_SEARCH_RESULTS`
  200, `MAX_SEARCH_DEPTH` 24, `MAX_TREE_DEPTH` 3; excluye `.git`,
  `node_modules`, `target`).
- `cli/src/comandos/web_datos/git.rs` — estado Git local de solo lectura
  (`status --porcelain=v1 -z` + `diff --unified=3`, timeout 5 s); devuelve
  `aplicable:false` cuando el workspace no es un repositorio Git (no error).

### Archivos modificados
- `cli/src/comandos/web_datos/mod.rs` — `mod files; mod git;` + re-exports.
- `cli/src/comandos/web.rs` — 5 rutas GET registradas:
  `files/info`, `files/listar`, `files/leer`, `files/buscar`, `git/estado`.
- `desktop/ui/src/adaptadores/api.ts` — 5 stubs que lanzaban error en modo web
  sustituidos por llamadas HTTP reales (`workspaceInfo/ListarEntrada/
  LeerArchivo/Buscar/GitEstado`).
- `desktop/ui/src/main.ts` — el visor habilita `leerArchivo` también en modo
  web (`USA_REAL`, no solo Tauri).
- `desktop/ui/src/estilos/{variables,layout,files,git,visor}.css` — cabeceras
  unificadas a `--alto-cabecera: 46px` (tarea previa de estética, mismo commit
  de UI).

### Decisiones
- Port, no compartición: `desktop/src-tauri` es crate aparte que no puede
  importar código de `cli`; se portó la lógica pura con tipos `Serialize`.
- Solo lectura (GET); sin commit/push/pull en web, igual que el modo Tauri.
- Raíz no aceptada desde la UI: se resuelve del workspace activo de la sesión.
- Variables locales renombradas (`io`/`stderr`/`err_bytes`) para no sombrear
  la función `error()` del módulo `web_datos`.

- `npm run build` (UI): OK, dist con hash `index-DueWVp-n.js`.
- Gate `sentinel check 089A-10 --stages scripts/quality/stages.json`: **PASS,
