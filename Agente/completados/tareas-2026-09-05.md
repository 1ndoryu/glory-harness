## 039A-3 P6-front (+): Menú hover de detalle del uso de la ventana de contexto

- Qué: requisito del usuario ("hace falta un pequeño menú contextual cuando se ponga el cursor
  sobre el círculo que diga detalladamente el uso de la ventana de contexto"). Al hacer hover o
  foco sobre el `.ctx-indicador` (círculo de contexto) se abre un pequeño menú informativo
  `.ctx-detalle` con el detalle del uso de la ventana; se cierra al salir.
- Archivos:
  - `desktop/ui/src/componentes/entrada.ts` — interfaz exportada `EstadoContexto` (`pct`,
    `maxVentana`, `reservaSalida`, `totalEntrada`); `setContexto(estado)` guarda el estado
    completo y pinta el arco; menú `.ctx-detalle` (`abrirDetalle`/`cerrarDetalle`) con
    `mouseenter`/`focus` abre y `mouseleave`/`blur`/click fuera/Escape/resize/scroll/blur cierra;
    posicionado con el vuelco de `menu.ts` (margen 8, bajo el rect, invierte si no cabe); contenido
    `filasDetalleContexto` (usados/reserva/entrada con números exactos `toLocaleString('es')` y
    separador de miles; "sin datos" si no hay turno, "configurada N" si solo hay `max_ventana`).
    Se elimina el `title` nativo del círculo (lo sustituye este menú custom).
  - `desktop/ui/src/componentes/panelChat.ts` — `setContexto(estado: EstadoContexto)` en la
    interfaz y la API `PanelChat` (delega en `entrada.setContexto`); en la rama mock de
    `alTerminar` pasa `{pct:7, maxVentana:150000, reservaSalida:20000, totalEntrada:9100}`
    (espejo del pie mock, para verificación visual).
  - `desktop/ui/src/main.ts` — `onContexto(u)` propaga el `EstadoContexto` completo (pct +
    maxVentana + reservaSalida + totalEntrada) a `panelesRegistrados`.
  - `desktop/ui/src/estilos/entrada.css` — `.ctx-detalle` (position:fixed, z-index 110 por encima
    de `.menu-ctx`, `pointer-events:none`, monocromo, white-space:nowrap), `.ctx-detalle-titulo`
    (opacity .6, border-bottom), `.ctx-detalle-fila` (flex etiqueta/valor).
- Evidencia:
  - `npm run type-check` + `npm run build` (desktop/ui) limpios (dist 66.08 kB JS, 17.53 kB CSS).
  - Verificación funcional en navegador mock (`VITE_MOCK=1`, puerto 8765): (a) hover inicial →
    "ventana de contexto / uso / sin datos"; (b) tras turno mock → "usados 9100 de 150.000 (7%) /
    reserva de salida 20.000 / entrada del turno 9100" (círculo `contexto 7%`, dashoffset 52.59);
    (c) al salir del círculo el detalle se cierra (0 nodos `.ctx-detalle`) y al re-entrar se reabre;
    (d) el panel lateral (entrada mínima, 2º `.ctx-indicador`) también muestra el detalle con el
    mismo estado "sin datos".
  - Capturas: `C:/tmp/glory-harness-p6-hover-detalle.png`,
    `C:/tmp/glory-harness-p6-hover-lateral.png`.
- Decisiones/gotchas:
  - El detalle es INFORMATIVO (sin ítems accionables): `pointer-events:none` para que lo abra y
    cierre el hover del propio círculo y nunca bloquee otros menús; `z-index` 110 por encima de
    `.menu-ctx`.
  - No se reutilizó `menu.ts` (`.menu-ctx` se cierra por click fuera y tiene `pointer-events:auto`);
    el detalle es un componente propio porque su ciclo de vida es hover (abrir/cerrar por
    mouseenter/mouseleave), no click.
  - Fuente única de datos = el mismo `ContextoDetalle`/`UsoTurno` del indicador (§2.10); se
    sustituye el `title` nativo del navegador por este menú custom (coherente con el detalle y la
    estética).
  - Números EXACTOS con separador de miles (`toLocaleString('es')`) en el detalle (no
    `tokensCortos` con sufijo k) para que el hover diga el uso con precisión; el pie conserva el
    formato corto.
  - Se respetaron los cambios ajenos del agente paralelo (`cli/src/ui/tui/*` y untracked de
    `desktop/src-tauri/`); `git add` explícito solo de los 4 archivos del front.
- Commit: `a69c2a3` — "039A-3 (P6 front): menú hover de detalle del uso de la ventana de contexto".
